# HFinger 升级实施路线图

## 1. 文档目的

本文档用于定义 HFinger 从当前版本升级到“服务端指纹识别引擎”目标状态的实施顺序、阶段目标和验收标准。

本路线图遵循以下前提：

1. 不兼容旧版 `finger.json`
2. 现有规则全部迁移并内置到程序中
3. 后续社区规则采用 YAML 外置
4. 本阶段先输出规划文档，待审核通过后再进入实现

## 2. 实施原则

### 2.1 先地基，后能力

优先搭建规则体系和工程基础设施，不先堆新识别能力。

### 2.2 先追平竞品基线，再做差异化

先追平 WhatWeb / xapp 已证明有价值的 Web 指纹能力，再做服务端基础设施识别、证据化和被动产品化。

### 2.3 先保证默认可用，再开放扩展

优先保证核心规则内置可用，再追加社区规则扩展入口。

## 3. 总体阶段划分

```text
P0 文档与方案阶段
P1 规则基础设施阶段
P2 引擎替换阶段
P3 Web 指纹基线追平阶段
P4 证据化与结果模型阶段
P5 服务端基础设施识别阶段
P6 被动模式产品化阶段
P7 规则治理与社区协作阶段
P8 AI 辅助增强阶段
```

## 4. 分阶段说明

## P0 文档与方案阶段

### 目标

明确升级目标、范围、规则模型和实施顺序。

### 产物

- `docs/FINGERPRINT_TARGET_AND_SCOPE.md`
- `docs/RULES_V2_SPEC.md`
- `docs/IMPLEMENTATION_ROADMAP.md`

### 完成标准

- 团队对目标范围达成一致
- 确认不兼容旧规则
- 确认核心规则内置策略

## P1 规则基础设施阶段

### 目标

先把规则作为“工程资产”管理起来，而不是继续把规则当静态 JSON 数据。

### 任务

1. 建立 `rules/` 目录结构
2. 建立 YAML schema
3. 实现规则解析器
4. 实现规则校验器
5. 实现 `rules lint`
6. 实现 `rules test`
7. 实现 `rules compile`

### 预期新增模块

- `rules/`
- `internal/rules/loader`
- `internal/rules/schema`
- `internal/rules/lint`
- `internal/rules/tester`
- `internal/rules/compiler`

### 完成标准

- 任意一条 YAML 规则可以被正确解析
- 非法规则可以被 lint 拦截
- 规则可以通过 fixtures 回放测试

## P2 引擎替换阶段

### 目标

将当前基于 `config.Config.Finger` 的匹配链路替换为新的规则执行链路。

### 当前待替换链路

```text
LoadFingerprintConfig
-> Config.Finger
-> matchKeywords
-> AddResults
```

### 新链路目标

```text
LoadBuiltinRules
-> LoadExternalRules
-> RunProbe
-> Match
-> Score
-> EmitResult
```

### 任务

1. 引入新的运行时规则结构
2. 新建 probe 执行层
3. 新建 matcher 执行层
4. 新建 scoring 层
5. 替换现有扫描逻辑中的旧匹配入口

### 完成标准

- 工具运行时不再读取 `data/finger.json`
- 内置规则可以完成基础识别流程
- 旧 `config.Fingerprint` 不再作为核心运行模型

## P3 Web 指纹基线追平阶段

### 目标

补齐 WhatWeb / xapp 级别的主流 Web 指纹识别能力，至少不落后于当前竞品基线。

### 第一批必须支持的 matcher

1. `body.contains`
2. `body.regex`
3. `header.contains`
4. `header.regex`
5. `title.contains`
6. `cookie.contains`
7. `status.eq`
8. `status.in`
9. `favicon.hash`
10. `path.exists`
11. `redirect.to`
12. `script.src.contains`
13. `html.meta.contains`

### 任务

1. 迁移现有旧规则为 V2
2. 补足缺失 matcher 的运行时支持
3. 建立一批规则样本和回放测试

### 完成标准

- 当前版本已有 Web 指纹识别能力全部迁移完成
- 新版本能覆盖主流 Web 指纹识别场景
- 输出结果不弱于当前版本

## P4 证据化与结果模型阶段

### 目标

让每个结果都可以解释“为什么命中”，并支持置信度表达。

### 任务

1. 重构结果结构
2. 为 matcher 输出证据
3. 引入置信度或评分结果
4. 更新 JSON/XML/XLSX 输出层

### 建议结果模型

至少包含：

- 目标
- 命中产品
- 类别
- 证据列表
- 置信度
- 状态码
- Server
- Title

### 完成标准

- 每条识别结果至少包含 1 条证据
- JSON 输出可完整表达证据
- CLI 输出可显示简化证据摘要

## P5 服务端基础设施识别阶段

### 目标

将 HFinger 从“Web 指纹工具”提升为“服务端指纹工具”。

### 优先级

1. CDN
2. WAF
3. 负载均衡
4. API 网关
5. TLS 证书与 ALPN
6. 常见协议服务 banner

### 任务

1. 设计基础设施类规则分类
2. 增加 TLS / banner / provider 类 matcher
3. 引入更适合基础设施识别的数据字段

### 完成标准

- 至少支持一批常见 CDN/WAF/LB/Gateway 识别
- 结果中可区分“应用层产品”和“基础设施层产品”

## P6 被动模式产品化阶段

### 目标

将当前被动模式从“能识别”提升为“可沉淀、可查询、可导出”的能力。

### 任务

1. 统一被动识别结果结构
2. 增加被动识别结果落盘
3. 增加去重与聚合
4. 增加查询和导出能力

### 说明

本阶段先不强求 UI，优先做数据层和 CLI 层。

### 完成标准

- 被动识别结果可结构化存储
- 可按目标、产品、时间维度检索

## P7 规则治理与社区协作阶段

### 目标

让规则库具备长期维护能力。

### 任务

1. 弱规则检测
2. 重复规则检测
3. 高误报规则提示
4. fixtures 规范
5. 贡献模板
6. 社区规则更新机制

### 完成标准

- 规则 PR 能自动校验
- 新规则贡献有明确模板
- 规则库可持续迭代

## P8 AI 辅助增强阶段

### 目标

使用 AI 增强规则生产和分析能力，而不是替代规则引擎。

### 合理边界

AI 只做辅助，不直接成为默认最终判定链路。

### 任务

1. AI 生成候选规则
2. AI 给出规则优化建议
3. AI 标记未知技术栈候选
4. AI 辅助解释识别结果

### 不建议事项

1. 不让 AI 直接无证据地产生最终命中结果
2. 不让 AI 绕过规则测试流程直接入库

## 5. 推荐执行顺序

按最实际的推进顺序，建议依次执行：

1. P0 文档与方案阶段
2. P1 规则基础设施阶段
3. P2 引擎替换阶段
4. P3 Web 指纹基线追平阶段
5. P4 证据化与结果模型阶段
6. P5 服务端基础设施识别阶段
7. P6 被动模式产品化阶段
8. P7 规则治理与社区协作阶段
9. P8 AI 辅助增强阶段

## 6. 第一批实现建议

若本规划获批，建议第一批实施只做以下内容，不扩散：

### M1

规则基础设施最小闭环：

- YAML schema
- `rules lint`
- `rules test`
- `rules compile`
- 核心规则内置

### M2

引擎切换最小闭环：

- 替换 `finger.json` 运行时依赖
- 支持基础 matcher
- 跑通主动模式

### M3

结果重构最小闭环：

- 基础 evidence
- 基础 confidence
- JSON 输出升级

## 7. 风险清单

### 7.1 规则迁移成本

现有规则数量较大，迁移成本不可忽略。

### 7.2 一次性重构风险

由于本次不保留兼容层，需要特别重视测试和阶段性验收。

### 7.3 被动模式复杂度

被动模式涉及流量、证书、代理行为，建议放在核心引擎稳定之后。

### 7.4 输出模型变更影响

结果结构升级后，README、示例和输出格式都需要同步调整。

## 8. 审核关注点

在开始实现前，建议重点审核以下事项：

1. 是否确认完全放弃旧版 JSON 运行时模型
2. 是否认可“核心规则内置 + YAML 外置”的长期方向
3. 是否认可优先级顺序：先规则基础设施，再引擎替换，再能力扩展
4. 是否认可 HFinger 的定位是“服务端指纹识别引擎”，而不是漏洞扫描器

## 9. 结论

本路线图的核心判断是：

1. 当前 HFinger 值得继续做，但不能再停留在旧 `finger.json` 阶段
2. 下一阶段最关键的不是先加更多指纹，而是先完成规则体系升级
3. 只有规则体系和引擎先稳定，后续证据化、基础设施识别、被动产品化和 AI 增强才有落地基础
